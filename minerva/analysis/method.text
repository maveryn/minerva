Retrieval method selection for label-hint curriculum

We select a retrieval method per label family to construct candidate pools for
label-hint curriculum training. The evaluation uses the Minerva dataset outputs
under dataset/minerva (generated by minerva/pipeline.py), excluding the CVSS
tasks (cve_to_cvss_v31 and cve_to_cvss_v40) since they are not ID retrieval
problems. For each remaining task, we sample up to 1,000 examples (uniform
random without replacement, seed 1337) from the JSONL files. Queries are drawn
from the task inputs (e.g., scenario text, Sigma excerpts, CAPEC examples, CVE
descriptions). Gold labels come from the task ground_truth fields.

Corpora are constructed from official sources to align with label spaces:
- ATT&CK techniques, tactics, mitigations, and detection strategies are read
  from the MITRE Enterprise ATT&CK bundle (dataset/mitre/enterprise-attack.json).
- CAPEC patterns are read from the CAPEC STIX bundle
  (dataset/capec/stix-capec.json).
- CWE weaknesses are read from the CWE XML catalog
  (dataset/cwe/cwec_v4.19.xml).
- Threat actors use ATT&CK intrusion-set names and aliases as labels; corpus
  texts concatenate name, aliases, and description.

Each corpus document is built as "name. description" (when available). We
sanitize corpus texts by removing URLs and explicit ID strings (e.g., T####,
TA####, DET####, M####, CWE-#, CAPEC-#) to prevent trivial ID matching in
retrieval. Detection strategy IDs are normalized by removing hyphens (DET-#### →
DET####), and all IDs are uppercased for matching.

Retrieval methods

1) BM25 (sparse). We tokenize by lowercasing and splitting on non-alphanumeric
   characters. We compute BM25 Okapi scores with k1=1.5 and b=0.75.
2) Dense. We encode queries and corpus documents with the sentence-transformers
   model "all-MiniLM-L6-v2" and use cosine similarity (dot product of
   L2-normalized embeddings).
3) Hybrid. We fuse normalized scores from BM25 and dense retrieval by
   S(d) = (1 - alpha) * BM25_norm(d) + alpha * Dense_norm(d), with alpha in
   {0.1, 0.2, ..., 0.9}. Min-max normalization is applied independently to the
   BM25 and dense score vectors per query.

Evaluation protocol

For each task and for each label family, we compute mean reciprocal rank (MRR)
over the sampled queries. For multi-label tasks (e.g., tactic IDs or mitigation
IDs), a query is counted as a hit if any of the gold labels appears in the
ranked list. We report MRR for BM25, dense, and each hybrid alpha, then select
the best method (and alpha) per label family. The chosen method is used for
building candidate pools in the label-hint curriculum.

Outputs

We save per-task and per-label-family MRR metrics, as well as the selected
method, to minerva/analysis/retrieval_selection/retrieval_selection.json. We
also save qualitative examples (five per label family) with the top-5 retrieved
labels in minerva/analysis/retrieval_selection/retrieval_examples_top5.jsonl.
