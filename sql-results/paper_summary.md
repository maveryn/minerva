# MinervaRL Summary

We adapt the Minerva Noctua/ACR framework to the SQL-R1 setting by keeping the SQL-R1 dataset and executable reward while replacing the original CTI output space with SQL generation. Concretely, we train from `Qwen2.5-Coder-3B-Instruct` on the SQL-R1 public SynSQL split (`example_data/train.parquet` for training and `example_data/test.parquet` for validation) using the SQL-R1 reward with database execution. Our main run uses an RL batch size of `128`, `8` GRPO rollouts per prompt, maximum prompt/response lengths of `4096/2048`, learning rate `3e-7`, and KL coefficient `0.001` on `8` GPUs. We first run a fixed `100`-step job and then resume training; the best validation checkpoint used for reporting is the checkpoint selected at step `400`.

For the Noctua-specific adaptation, we use SQL-conditioned ACR prompts and gate hard examples by `exec_match` rather than by the raw scalar reward. The ACR path uses `4` ACR rollouts, deferred generation, an EMA teacher, and SFT distillation every `10` steps with flush-mode buffering and distillation batch size `256`. Evaluation follows the SQL-R1 self-consistency protocol: we sample `8` candidates at temperature `0.8` and select the final SQL by execution-based major voting. On the six benchmark splits we report, the step-400 MinervaRL checkpoint reaches `69.87` average execution accuracy, compared with `67.97` for the base `Qwen2.5-Coder-3B-Instruct` model and `68.71` for the released `SQL-R1-3B` model when taking the best score per dataset across three reruns.
